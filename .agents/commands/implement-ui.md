# implement-ui

Implement the approved visible client behavior.

## Input
Approved UI/flow design, acceptance criteria, change plan, available state interface, existing components and styling conventions.

## Gate
The plan changes visible behavior or interaction.

## Steps
1. Identify the affected user or admin screens/components and implement approved layout, content, interactions, and states within project conventions.
2. Connect to the established state interface. Cover relevant loading, empty, error, and success states when specified by the design.
3. Update meaningful UI tests or checks. Report missing visual or interaction decisions that block the requested behavior.

## Output
Changed UI files and relevant tests or checks.

## Done when
The visible behavior meets approved acceptance criteria and is ready for final verification.
